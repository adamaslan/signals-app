What "Signals" Means in This App

A signal is a directional call (strong buy → strong sell) on one ticker, assembled by running ~18 independent technical detectors over OHLCV data, ranking them by confluence, and optionally passing the result through an LLM for a written rationale. The stages below run on every GET /signals/{symbol} request.

L1
Fetch OHLCV
L2
Compute indicators
L3
Detect signals
L4
Confluence rank
L5
LLM synthesis
Backend Signal detection — 18 detectors, 3 categories src/signals_app/detection/
Each detector reads the latest 1–2 bars of the indicator DataFrame and independently emits zero or more MutableSignal objects (label, strength, category). A per-detector thread-pool timeout means one slow or failing detector degrades the result rather than crashing the request — orchestrator.py marks the response degraded if too many detectors fail.

Signals then pass through ConfluenceRanker (L4), which counts bullish vs. bearish signals into a bull_count / bear_count / score, and compute_multi_timeframe, which maps the requested period (1d…1y) to a timeframe label (1D…1Y) for synthesis.
Backend LLM synthesis & API surface src/signals_app/synthesis/, api/routes.py
synthesize_single() feeds the confluence result plus current indicator values (RSI, MACD, ADX, Close, Volume, ATR, Price_Change) to an LLM prompt, which returns a structured Signal: a direction, confidence (0–1), and an evidence list. If the LLM call fails or is disabled (no_llm=true or no key configured), a rule-based _fallback_signal() is returned instead and flagged ai_degraded — the pipeline never 500s just because the LLM is unavailable.
EndpointPurpose
GET /signals/{symbol}Full pipeline (L1–L5) for one ticker; params period, no_llm.
GET /history/{symbol}Past runs for a ticker from the SQL DB, newest first (paginated).
GET /healthLiveness probe.
Every run is persisted via record_run() (ticker, period, direction, confidence, degraded flags) — fire-and-forget, so a DB write failure is logged but never fails the response.
Frontend Rendering a signal web/src/components/SignalCard.tsx, ConfluenceBar.tsx
SignalCard is the primary unit of display: one ticker, one synthesized direction. Confidence drives the visual weight directly — card opacity is 0.3 + 0.7 × confidence and border width is 1 + 4 × confidencepx, so a low-confidence call visibly recedes rather than needing a separate label to read as "weak."

Evidence items (the individual detector hits feeding the call) are collapsed by default behind a "Show N evidence items" toggle. An ⚠ AI unavailable badge appears whenever ai_degraded is true, so a rule-based fallback is never presented as if it were LLM-reasoned. ConfluenceBar separately visualizes the raw bull/neutral/bear signal split as a segmented bar, plus a multi-timeframe "alignment score" bar (green >70%, amber 40–70%, red <40%) showing how much the different timeframes agree.

Issues & Fixes

Fixed Missing mamba environment
Problem
No signals-app mamba env existed yet, so the backend couldn't import signals_app at all.
Fix
mamba env create -f environment.yml -y
mamba install -n signals-app -c conda-forge aiosqlite -y
Note
aiosqlite is used by db/session.py and listed in pyproject.toml, but was missing from environment.yml — added manually.
Fixed Port 8000 already occupied by an unrelated project
Problem
Port 8000 was already bound by a long-running uvicorn process from an unrelated project (social-pr-autopilot). Starting signals-app's backend there would have silently talked to the wrong service — not something to kill without asking first.
Fix
Ran the signals-app backend on :8010 instead, and pointed the frontend at it via web/.env.local:
BACKEND_URL=http://localhost:8010
Fixed SSR crash: localStorage.getItem is not a function
Problem
Every server-rendered route returned 500. Root cause: Node 25 (the local node is v25.8.2) ships an experimental global localStorage that exists but isn't fully functional. Dexie (web/src/lib/db.ts), imported transitively during SSR, feature-detects it as present and tries to use it, then throws. Next.js 15.3.3 / React 19 predate Node 25, so this combination was never targeted by the app.
Fix
Disabled the experimental API for the dev process rather than touching app code:
NODE_OPTIONS="--no-experimental-webstorage" npm run dev
Open .claude/commands/dev.sh breaks when copied elsewhere
Problem
The script resolves its own directory and does cd "$SCRIPT_DIR/web", so it only works if invoked from the repo root. It also calls mamba run -n signals-app uvicorn ... directly, which did not reliably inherit PYTHONPATH in this session.
Workaround used
Started backend and frontend as two separate background commands instead of via the script.
