The button doesn't scan. It reads.

"Run basket (5d)" in the web UI never touches yfinance, an LLM, or a detector. It runs one batched Supabase query against whatever the Python scanner already wrote. If the scanner never ran for that period, the button faithfully reports that nothing is there — that's what partial · 954 uncovered meant, not a bug.

Coverage vs. gate — two different reasons a ticker shows "uncovered"

A row is missing from latest_signals for one of two reasons, and the UI can't tell them apart — both render identically as error: "uncovered". Try the sliders: real confluence rarely clears 0.35, which is deliberate — "most ticker-days should fail this gate" is a comment straight out of scanner.py.

Seeing your 5d scan

You ran scan_universe.py --seed seed/universe_symbols.csv --period 5d. The "partial · 954 uncovered" screenshot was taken before that — the UI never refreshes itself, so it's still showing the old run. Three steps to see what actually landed.

1

Confirm the scan actually wrote something

Your terminal printed a summary line when it finished. That line is the ground truth for what got published — not the UI.

scan_universe: 954 symbols, 954 ok, 0 failed, N published, Ts

Expect: ok ≈ 954 (yfinance fetches succeeded). published will be small — single digits to low dozens is normal for one day's 5d scan, because of the gate above. published = 0 with ok > 0 is not an error, it's "nothing cleared 0.35 confluence today."

2

Spot-check one ticker from the CLI

Pick a ticker you'd bet moved this week and ask the engine directly — this bypasses the web UI and Dexie cache entirely, straight to Supabase.

cd /Users/adamaslan/code/signals-app
mamba run -n signals-app python -m signals_app.cli.main history AAPL --limit 5

Expect: a row with period=5d and today's date if AAPL cleared the gate; an empty table if it didn't (try a more volatile name from your seed list instead).

3

Re-run the basket in the UI — don't just reload

The Universe page doesn't poll. Opening it again shows the same stale Dexie-cached run from before your scan. You have to trigger a new read.

Universe → open your universe → Run basket (5d) button
              → wait for "running" to flip to "complete" / "partial"
              → toggle table / heatmap to see per-ticker results

Expect: uncovered count drops from 954 by however many tickers cleared the gate today. Going from 954→954 uncovered again most likely means the gate published nothing — re-check step 1's "published" count before assuming the UI is broken.
